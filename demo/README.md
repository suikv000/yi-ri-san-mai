# 一日三麦 · Skill 交互演示 v1.5

白色页面、黑色文字标识，少量红黄强调。日期下方用同心三层环显示当天热量、蛋白质和脂肪；超目标明确标出，满环不代表营养全面。

本项目展示 AI Skill 的规划与调整输出；尚不是完整宿主安装包，不会下单或创建定时任务。

## 打开与修改

打开 `demo/index.html`，或双击上一级 `一日三麦-交互演示.html`。源码修改后，在项目根目录运行：

```
node demo/build.cjs
node demo/verify.cjs
```

官方食物图片依赖网络。计算与交互在浏览器本地运行，不包含 MCP Token。

## 本次实际改变

- 比较单点、1+1、官方组合、套餐及加购，不再强制每餐三件。
- 38 个有营养对应的购买单元，天津时代奥城三店合计 95 条单元报价记录；56 个具备本地购买路径的配餐候选。
- 同样食物数量用精确多重集合覆盖比较购买路径，选择已知单元中的低价买法。两个汉堡不能被当作一个汉堡计价。
- 各店独立计算购买路径。该店缺报价或缺选项时不可引用其他店价格，不把“13.9 元起”当成所有 1+1 的价格。
- 整周有限候选试排：预算硬上限，兼顾每日能量、蛋白质缺口、钠、脂肪、价格、重复度和距离。不是已证明的整周全局最优。
- 每套显示蛋白质/元、蛋白质/100千卡；展开可见购买单元与三店价格。详细比较表支持按门店、单点/组合、性价比排序。
- 先填条件再生成；单餐随机或手选不改其他 20 餐，不自动锁定。支持锁定、整周重排、撤销、主动保存与导出。
- 保留原本浏览器存储键，改名不主动清除存档。旧的上海示例门店草案无法直接映射天津门店时展示新示例，旧原始存储不会在加载时删除；再次保存会覆盖本页草案。

## 数据及边界

- 天津时代奥城是用户指定的示例地点。接口发现 5 店，最近 3 店完成样本核价；当前没有公司地点或真实通勤路线。
- 正餐为 2026-10-18 核价；早餐预约 2026-10-19 08:15。未来一周的价格与供应要临餐复核。复合加购按已核价单元相加，未穷举整单再次核价。
- 距离来自门店接口。分钟数仅按 80 米/分钟换算，不是地图步行时间或上下班绕路时间。
- 购买价格和营养是独立来源：营养来自官方 MCP 160 条记录中筛选的精确匹配食品；没有精确匹配的新品套餐不编造营养。
- 当前未验证个人卡券。新候选采用未指定优惠券、未随单购卡的报价，不再虚减“早餐每次2元”“正餐每次2.5元”。卡费假设仍计入所选预算，未验证权益不推荐购卡。
- 本周现金口径含新卡全额；折算口径含周分摊。未使用卡费仍保留，不会凭空归零。
- 身体参数只用于一般成人估算。钠、脂肪或其他缺口仍需调整；纤维、饱和脂肪和过敏原缺失，不视为零。
- 没有调用账户、购买、领券、订单、支付工具。自动任务、手机宿主接入和实际下单未实现。

## 文件

- `data.js`：脱敏公开食品、购买单元、各店报价及示例地点。
- `planner.js`：同店购买路径、可用性、周预算约束、营养评分与换餐。
- `nutrition.js`：身体参数参考估算；`app.js`：交互与同心环。
- `index.html`、`styles.css`：界面；`build.cjs`：单文件；`verify.cjs`：核心验证。
- 上一级 `一日三麦-配餐与天津周边比价分析-v1.5.md`：实际比价、蛋白质分析、取舍与待实现部分。
